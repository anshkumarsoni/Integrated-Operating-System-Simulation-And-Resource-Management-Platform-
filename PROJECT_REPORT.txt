2. PROBLEM STATEMENT & OBJECTIVES
--------------------------------------------------------------------------------
2.1 The Problem:
Core operating system abstractions (process scheduling, dynamic memory fragmentation, deadlock arbitration, and disk arm dispatching) are traditionally taught as isolated, theoretical algorithms. Existing tools lack real-time visual synchronization and fail to demonstrate how low-level OS kernel lifecycles integrate with persistent relational database management systems (DBMS).

2.2 Finalized Measurable Objectives:
1. Synchronized Kernel Orchestration: Model dynamic Process Control Blocks (PCBs) across canonical state transitions (NEW -> READY -> RUNNING -> WAITING -> TERMINATED).
2. Autonomous Scenario Classifier: Implement real-time workload variance evaluation (CV = sigma / mu) to detect convoy risks and auto-assign optimal scheduling algorithms.
3. Multi-Tier Memory & Deadlock Safety: Model dynamic contiguous allocation (First/Best/Worst Fit with hole coalescing), Demand Paging (FIFO/LRU/Optimal), and Banker's Algorithm safe sequence discovery.
4. 5-Layer Relational Integration: Durably persist kernel states, audit logs, and ACID transactions into a normalized MySQL 8.0 schema with query latency < 1ms and live analytical summary views.
5. Dual-Mode Zero-Crash Reliability: Implement both a live MySQL backend bridge and a client-side deterministic fallback engine to guarantee uninterrupted execution during offline presentations.

4. DETAILED TECHNICAL MODULES & ALGORITHMS
--------------------------------------------------------------------------------
4.1 Kernel Engine & PCB State Machine:
- PCB Object Model: Tracks PID, name, state, arrival_time, burst_time, priority, cpu_registers (EAX, EBX, ECX, EDX), program_counter (e.g. 0x004012A0), and memory_allocation boundaries (base_address, limit).
- State Transitions: NEW -> READY -> RUNNING -> WAITING -> TERMINATED.

4.2 CPU Scheduling & Autonomous Classifier:
- Implemented Algorithms:
  1. FCFS (First-Come, First-Served): Non-preemptive, arrival-ordered.
  2. SJF (Shortest Job First): Non-preemptive optimal throughput for batch jobs.
  3. SRTF (Shortest Remaining Time First): Preemptive SJF re-evaluating remaining burst time at each clock tick.
  4. Round Robin (RR): Circular queue with calibrated quantum (q = 2ms) and remaining burst tracking.
  5. Preemptive Priority: Immediate preemption for critical tasks (0ms dispatch delay).
- Autonomous Scenario Classifier:
  Computes the Coefficient of Variation (CV) of burst times:
  CV = sigma / mu = Standard_Deviation / Mean_Burst_Time
  - If CV > 0.8: Flags danger of the Convoy Effect under FCFS; auto-recommends SRTF or Round Robin.
  - If CV <= 0.8: Recommends FCFS or Priority based on task urgency.

4.3 Contiguous Memory Partitioning & Dynamic Hole Coalescing:
- Placement Policies: First Fit, Best Fit (minimizes internal fragmentation), and Worst Fit.
- Fragmentation Metrics:
  Internal Fragmentation = Partition Size - Requested Size
  External Fragmentation = Sum of all free blocks when no single block fits.
- Hole Coalescing Algorithm:
  Upon process termination, adjacent free memory blocks (Block[i].start + Block[i].size == Block[i+1].start) are merged into a single contiguous partition, restoring unfragmented memory space.

4.4 Virtual Memory & Demand Paging:
- Page Replacement Policies:
  - FIFO: Evicts the page resident longest in memory using an insertion queue.
  - LRU (Least Recently Used): Tracks access timestamps; evicts the least recently referenced frame.
  - Optimal (Belady's Algorithm): Looks ahead into future references; evicts the frame that will not be used for the longest period in the future.
- TLB Cache Simulation: 4-entry Translation Lookaside Buffer simulating hardware address translation with TLB Hit and Miss ratios.

4.5 Concurrency & Banker's Deadlock Avoidance:
- Data Structures:
  - Allocation[n x m]: Currently assigned resource instances.
  - Max[n x m]: Maximum claim per process.
  - Need[n x m] = Max - Allocation: Remaining resource requirement.
  - Available[m]: Unallocated resource vector.
- Safety Search Loop:
  Iteratively identifies process p where Finish[p] == false and Need[p] <= Work. Reclaims resources (Work = Work + Allocation[p]) until a verified Safe Sequence (e.g., <P1, P3, P4, P0, P2>) is produced. If unresolvable, flags DEADLOCK.
- Graph Visualization: Directed Resource Allocation Graph (RAG) and Wait-For-Graph (WFG) cycle detection.

4.6 Relational DBMS Backplane & ACID Transactions:
- Normalized MySQL Schema: 10 InnoDB tables (users, processes, pcb, memory_allocations, resources, system_calls, filesystem_nodes, threads, io_requests, execution_history).
- Two-Phase Locking (2PL) ACID Engine:
  - Implements BEGIN TRANSACTION, SELECT ... FOR UPDATE (exclusive row locks), atomic state mutations, and COMMIT.
  - Injects simulated hardware crashes to demonstrate automated ROLLBACK restoring invariants with zero data loss.
- EXPLAIN Query Optimizer: Evaluates query cost comparing B-Tree primary index lookups against full table scans.
- Summary Views: v_process_summary, v_memory_fragmentation, v_io_latency, and v_system_health.
